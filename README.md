# Git Merge Conflict Demo

## Objective

This project demonstrates how to create and resolve a Git merge conflict using Python and Git.

The exercise demonstrates:

1. Creating two branches from the same base commit.
2. Making different changes to the same line of `main.py`.
3. Merging the first branch into `main`.
4. Attempting to merge the second branch and creating a real merge conflict.
5. Understanding Git conflict markers.
6. Manually resolving the conflict.
7. Committing the conflict resolution.
8. Verifying the complete Git history.

# Initial Python Program

The initial `main.py` contains:

```python
print("Hello from main")
```

This file is committed to the `main` branch before creating the feature branches.

---

# Step 1: Initialize Git Repository

Create the repository:

```bash
git init
```

Rename the default branch to `main`:

```bash
git branch -M main
```

Check the status:

```bash
git status
```

Add the Python file:

```bash
git add main.py
```

Create the initial commit:

```bash
git commit -m "Initial commit"
```

This initial commit is the common base for both feature branches.

---

# Step 2: Create Feature Branch A

Create the first branch:

```bash
git checkout -b feature/message-a
```

Modify `main.py`:

```python
print("Hello from Branch A")
```

The original line:

```python
print("Hello from main")
```

was changed to:

```python
print("Hello from Branch A")
```

Commit the change:

```bash
git add main.py
git commit -m "branch a changes"
```

---

# Step 3: Create Feature Branch B from Main

Return to `main`:

```bash
git checkout main
```

Create the second branch:

```bash
git checkout -b feature/message-b
```

Modify the **same line** in `main.py`, but differently:

```python
print("Hello from Branch B")
```

The original line:

```python
print("Hello from main")
```

was changed to:

```python
print("Hello from Branch B")
```

Commit the change:

```bash
git add main.py
git commit -m "branch b changes"
```

At this point, both branches were created from the same initial commit.

---

# Step 4: Verify Both Branches Have the Same Base

This step provides direct Git evidence that both branches have the same parent commit.

Run:

```bash
git rev-parse feature/message-a^
```

Then:

```bash
git rev-parse feature/message-b^
```

Both commands must return the same commit ID.

For example:

```text
abc1234
abc1234
```

The actual commit ID in this repository will be different.

You can also verify the common ancestor using:

```bash
git merge-base feature/message-a feature/message-b
```

The result should be the same initial commit.

---

# Step 5: Verify the Actual Branch A Diff

Run:

```bash
git show feature/message-a -- main.py
```

The output should show the actual Git diff.

It should contain a change similar to:

```diff
-print("Hello from main")
+print("Hello from Branch A")
```

This proves that Branch A changed the original line.

The complete output of this command must be recorded in `git-evidence.txt`.

---

# Step 6: Verify the Actual Branch B Diff

Run:

```bash
git show feature/message-b -- main.py
```

The output should contain:

```diff
-print("Hello from main")
+print("Hello from Branch B")
```

This proves that Branch B changed the same original line differently.

The complete output of this command must also be recorded in `git-evidence.txt`.

---

# Step 7: View the Branch History

Run:

```bash
git log --oneline --graph --decorate --all
```

The history should show both branches coming from the same initial commit.

The exact commit IDs will be different, but the structure should be similar to:

```text
* branch b changes
|
| * branch a changes
|/
* Initial commit
```

Record the actual output in:

```text
git-evidence.txt
```

---

# Step 8: Merge Feature Branch A

Switch to `main`:

```bash
git checkout main
```

Merge Branch A:

```bash
git merge feature/message-a -m "Merge message-a into main"
```

This merge should complete successfully.

At this point, `main.py` contains:

```python
print("Hello from Branch A")
```

---

# Step 9: Merge Feature Branch B and Create the Conflict

Now attempt to merge Branch B:

```bash
git merge feature/message-b
```

Git should stop with a merge conflict.

The actual output should contain:

```text
CONFLICT (content): Merge conflict in main.py
Automatic merge failed; fix conflicts and then commit the result.
```

**Do not manually create this message.**

It must be the actual output generated by Git.

Run:

```bash
git status
```

Git should report that `main.py` has an unmerged conflict.

Record the actual merge output and `git status` output in:

```text
git-evidence.txt
```

---

# Step 10: Inspect the Conflict

Open `main.py`.

Git will insert conflict markers similar to:

```python
<<<<<<< HEAD
print("Hello from Branch A")
=======
print("Hello from Branch B")
>>>>>>> feature/message-b
```

The two versions are:

### Current version in main

```python
print("Hello from Branch A")
```

### Incoming version from feature/message-b

```python
print("Hello from Branch B")
```

---

# Step 11: Resolve the Conflict Manually

Remove the Git conflict markers and choose the final code.

Use:

```python
print("Hello from the resolved main branch")
```

The final `main.py` should contain only:

```python
print("Hello from the resolved main branch")
```

---

# Step 12: Test the Resolved Program

Run:

```bash
python main.py
```

Expected output:

```text
Hello from the resolved main branch
```

---

# Step 13: Commit the Conflict Resolution

Stage the resolved file:

```bash
git add main.py
```

Commit the resolution:

```bash
git commit -m "Resolve merge conflict between message branches"
```

This completes the second merge.

---

# Step 14: Verify the Final Git History

Run:

```bash
git log --oneline --graph --decorate --all
```

The final history should contain:

- Initial commit
- Branch A change
- Branch B change
- Merge of Branch A into main
- Final merge-resolution commit

A typical history will look similar to:

```text
*   Resolve merge conflict between message branches
|\
| * branch b changes
* | Merge message-a into main
|/
* branch a changes
* Initial commit
```

The actual commit IDs and graph formatting will depend on the repository.
